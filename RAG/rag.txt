Core RAG Components :

The four fundamental pillars of any RAG architecture: Document Loaders, Text Splitters, Vector Databases, and Retrievers.


1- DOCUMENT LOADRER-
document loaders are utility components designed to ingest data from diverse sources and convert them into a standardized format known as Document Objects . This process is a crucial first step in building RAG (Retrieval-Augmented Generation) applications, as it prepares raw data for subsequent tasks like chunking, embedding, and retrieval .

Core Characteristics:

Standardized Output: Every loader, regardless of the source (PDF, text, web, etc.), outputs a list of Document objects .
Structure: Each document consists of two primary components: page_content (the actual data) and metadata (contextual info like source, page numbers, or timestamps).
Commonly Used Loaders:

        TextLoader
        PyPDFLoader
        DirectoryLoader
        CSVLoader
functions->
.load(): Performs eager loading, pulling the entire dataset into memory at once. Best for smaller files .
.lazy_load(): Provides a generator that fetches documents one at a time on demand. This is highly recommended for large-scale data to minimize memory usage and stream processing

    VECTOR STORE VS VECTOR Database

vector store- a lightweight service or library designed primarily for two tasks: storing numerical vectors and performing semantic similarity searches. It is ideal for prototyping and smaller-scale applications where advanced database features (like complex access control or ACID transactions) are not strictly required. A common example is Faiss.

Vector Database : This is a full-fledged database system that includes all the functionality of a vector store, plus database like features. These features often include:
Distributed architecture for high scalability.
Durability and persistence (backups and restores).
ACID transaction support for data integrity.
Advanced security, such as role-based access control and authentication.

4-Retrievers

a retertiver is a component that fetches documents from a data source in response to a user's query.
They act like a search engine and all retrivers are runnables 

Types of Retrievers--
Retrievers can be categorized based on their data source or their search strategy :

Source-based:
Wikipedia Retriever: Queries the Wikipedia API to fetch relevant articles .
Vector Store Retriever: Performs semantic search within a vector database (e.g., Chroma, FAISS).

Strategy-based:
Maximum Marginal Relevance (MMR): Reduces redundancy in search results to provide more diverse information .
Multi-Query Retriever: Uses an LLM to generate multiple versions of a user's query to resolve ambiguity and improve retrieval accuracy.
Contextual Compression Retriever: Compresses retrieved documents by stripping away irrelevant text, keeping only content pertinent to the specific query .
